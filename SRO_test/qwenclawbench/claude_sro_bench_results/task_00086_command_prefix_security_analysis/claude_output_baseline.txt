### Two distinctly different injection vectors found:

1. **Command 1 (L24)** — Classic shell injection: `curl | bash` pipes an untrusted remote script directly into the shell interpreter. The `|` character is completely unquoted (INJ-004 / KI-002).

2. **Command 3 (L32)** — Application-layer **prompt injection**: while no shell metacharacters exist outside quotes, the combination of AI CLI (`claude`) + CJK prompt text containing fullwidth characters (`：` `，`) + `--dangerously-skip-permissions` matches all three criteria of Security Bulletin SAB-2025-001, creating an automated attack path for AI-generated destructive commands in a CI/CD context.

### Conflicts Identified (5 total)

The most significant is **Conflict D** — the Security Bulletin SAB-2025-001 (2025-01-08, ACTIVE) contradicts the security policy v3.2.0 (2025-01-10) on how to classify AI CLIs with non-ASCII content and permission bypass. I adopt the bulletin because:
- It addresses a distinct threat model (prompt injection) the policy never considered
- It cites CVE-2024-51234 and internal incidents
- `known_injections.json` KI-008 independently corroborates the approach
- The bulletin explicitly directs applying more restrictive classification in conflicts
- The policy's non-ASCII and flag-vs-injection rules remain authoritative for all non-AI CLI commands

### Recommendation

Both flagged commands should be escalated. The `curl | bash` pattern on L24 is the more conventional injection — replace with verified package installation or signed script execution. The `claude --dangerously-skip-permissions` with CJK text on L32 is the more novel threat — the pipeline should either remove `--dangerously-skip-permissions`, use English-only prompts, or gate the claude invocation behind manual approval.
